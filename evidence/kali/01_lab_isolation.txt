
### 1. Isolated lab network (Task 1 - lab isolation evidence)
Kali lab host interfaces and routes (in the VM run this is the VM; in the container run, the container):

$ ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128 
eth0@if16        UP             172.20.0.2/16 
cs-untr-h@if3    UP             10.10.50.1/24 fe80::9c50:37ff:fe6a:2e49/64 
cs-staff-h@if5   UP             10.10.60.1/24 fe80::3c83:48ff:fe08:bc07/64 

$ ip route
10.10.50.0/24 dev cs-untr-h proto kernel scope link src 10.10.50.1 
10.10.60.0/24 dev cs-staff-h proto kernel scope link src 10.10.60.1 
172.20.0.0/16 dev eth0 proto kernel scope link src 172.20.0.2 

$ ip netns list
cs_untrusted (id: 1)
cs_staff (id: 2)
Each lab zone only has a route to its own /24 - no default gateway, no Internet:

$ ip netns exec cs_untrusted ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128 
cs-untr-n@if4    UP             10.10.50.66/24 fe80::b03d:1bff:feb4:95c9/64 

$ ip netns exec cs_untrusted ip route
10.10.50.0/24 dev cs-untr-n proto kernel scope link src 10.10.50.66 

$ ip netns exec cs_staff ip route
10.10.60.0/24 dev cs-staff-n proto kernel scope link src 10.10.60.10 

$ ip netns exec cs_untrusted ip route get 1.1.1.1 || echo '=> no route: the untrusted zone cannot leave the lab'
RTNETLINK answers: Network is unreachable
=> no route: the untrusted zone cannot leave the lab
